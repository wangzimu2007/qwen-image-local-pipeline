# 视频生视频（已有视频 → 重新绘制 / 改风格）

本地现有模型里**没有 VACE/H3 的整段视频重绘能力**，所以用「关键帧重绘 + 插帧回填」实现，
纯本地、不依赖任何新模型。

## 1. 调用方式

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\qwen-image-2.1\视频生视频.ps1 `
  -Video "C:\Users\wangzimu\Desktop\视频\video-0002-wan-20261024-124801.mp4" `
  -Prompt "水彩画风格，柔和笔触，纸质感" -Every 8 -Strength 0.55 -NoPause
```

工具超时给 **≥ 1800000 ms**（每条关键帧约 13~25 秒 + 插帧）。

| 参数 | 默认 | 说明 |
|---|---|---|
| `-Video` | **必填** | 要改造的视频 |
| `-Prompt` | 水彩画风格… | 目标风格/内容，写"变成什么" |
| `-Every` | 8 | 每 N 帧抽一张重绘（**越大越快、越不连贯**） |
| `-Strength` | 0.55 | 重绘强度。0.4~0.5 保结构，0.7 以上接近重画 |
| `-Width/-Height` | 自动 | 重绘分辨率，默认跟随原视频 |
| `-KeepFrames` | — | 保留中间帧，便于排查 |

## 2. 流程（脚本内部）

1. 每 `-Every` 帧抽一张关键帧（PyAV），存临时目录
2. 逐张调 `改图.ps1`（Qwen 图生图）重绘
3. 用 PyAV 把重绘帧合成低帧率视频（fps = 原 fps / Every）
4. 调 `后期处理.ps1 -Interp Every` 把帧率补回原值
5. 归位编号 + 抽预览帧

## 3. 耗时换算（重要）

| 原视频 | Every | 关键帧数 | 预计总耗时 |
|---|---|---|---|
| 5 秒 @24fps | 8 | 16 | **约 4~7 分钟** |
| 5 秒 @24fps | 12 | 11 | 约 3~5 分钟 |
| 5 秒 @24fps | 4 | 31 | 约 8~13 分钟 |
| 2 秒 @16fps | 8 | 5 | **实测 1.1 分钟**（重绘）+ 4 秒（插帧）|

实测单个关键帧约 **13 秒**（640²，0.55 强度）。

## 4. 画质取舍

- **Every 越大 → 越省时间，但运动越"跳"**（插帧在关键帧之间生成过渡，运动细节会丢失）
- **Strength 越高 → 风格越彻底，但帧间一致性越差**（容易闪）
- 建议：先 `-Every 8 -Strength 0.5` 跑一条看看，再决定要不要加密

想避免闪烁的替代方案（更便宜）：**不做逐帧重绘**，直接用 `image-to-video` 拿首帧重新生成
一条同构图的新视频（几秒到几分钟），风格改得更彻底、也更连贯。

## 5. 跑完必须做

1. `present` 交付 **mp4 + 2 张预览帧**
2. 告诉用户去 `C:\Users\wangzimu\Desktop\视频\` 双击播放
3. 报告：原帧率/成片帧率、时长、关键帧数、总耗时
4. 提醒：**没有音频**；原视频的音频不会保留

## 6. 失败排查

| 现象 | 处理 |
|---|---|
| 某帧重绘失败 | 脚本自动用原图代替，成片会出现原色调的闪帧，可加大 Every 重跑 |
| sd.cpp 报 CUDA 错误 | 先重启系统；或改用 ComfyUI 的 Qwen-Image-Edit 工作流替代（慢很多） |
| 成片很卡 | 减少 `-Every`（加密关键帧），或降低 `-Strength` |
| 插帧没做 | 确认秋叶版 8189 能起来、`film_net_fp16` 在 `models\frame_interpolation\` |
