# 音频工作台逻辑优化记录（2026-10-28）

按 P0→P1→P2 分阶段实施，目标是**结果可信、重复操作更快、可连续排队**。

## P0 正确性（已完成）

| 改动 | 说明 |
|---|---|
| 产物识别 | `product_of()` 支持 `成品/视频完成/音频完成/编辑完成/超分完成/输出/RESULT=`，取最后一条存在的路径 |
| 旧文件误判 | `_collect()` 不再用 `latest()` 扫整个目录；只收**本次任务开始后**新生成的文件，失败时不再展示旧产物 |
| 失败状态 | `_collect()` 返回 `ok`；界面显示 `✓ 完成 · 产物已生成` / `✗ 任务失败 · 请查看运行日志`；TaskThread 异常也标记失败 |
| 路径记忆 | `PathRow` 用 QSettings 记住每个输入框上次路径（文件仍存在才恢复），重开工作台不用重选 |

验证：`product_of` 四种标签全部通过；PathRow 离屏重建后能恢复路径。

## P1 速度（分析缓存已完成）

| 缓存 | 位置 | 命中效果 |
|---|---|---|
| 视觉理解 + 配音提示词 | `D:\audio-tools\音频工作台\cache\dubprompt-*.json` | 跳过抽帧、qwen3-vl、qwen3.5 |
| 旁白 LLM 输出 | 同目录 `narration-*.json` | 跳过旁白生成 LLM |

- 缓存键包含视频路径/大小/mtime、用户提示词、模型名，视频变了自动失效
- 实测（4 秒视频，Kokoro）：
  - 第一遍 36.3 秒（生成缓存）
  - 第二遍 **10.8 秒**（命中缓存，日志显示「缓存命中」）
- 清理缓存：删掉 `D:\audio-tools\音频工作台\cache\dubprompt-*.json`、`narration-*.json` 即可

**F5 常驻已完成（2026-10-28）**：5_server.py 模型只加载一次，本地 8766 端口；空闲 600 秒自动退出。
先启动服务再复用：首次自动拉起 19.9 秒，第二次 **2.4 秒**（原来每次约 33 秒）。
Qwen TTS 仍为冷加载（单次加载约 7 秒，收益较小，暂未常驻）。

## P2 流程（已完成）

| 改动 | 说明 |
|---|---|
| 任务队列 | 运行中再点任务不再弹“请等它完成”，而是**加入队列**，当前任务结束后自动执行；状态栏显示排队数量 |
| 按钮可用性 | 运行中按钮保持可点（用于排队），不会重复并行执行；后台仍是串行 |
| 视频配音页分组 | 分为 ① 视频与音色 / ② 引擎与声音库角色 / ③ 旁白内容 / ④ 输出选项 |

验证：离屏实例化 12 个页签正常，`task_queue` 存在，声音库角色下拉 2 项。

## 使用方法

1. 关掉音频工作台，重新打开（新代码生效）
2. 视频配音页会看到 4 个分组标题
3. 跑任务时再点其他任务，会看到「＋ 已排队 N 个任务」
4. 同一视频重配时，日志出现「缓存命中」，明显更快
