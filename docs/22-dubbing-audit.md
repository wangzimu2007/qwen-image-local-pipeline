# 本地视频配音流程审计与修复（2026-10-27）

## 结论

流程**大体正确**，但有 9 个会直接影响成品的 bug，已全部修复并实测。

## 修掉的 bug

| # | 问题 | 影响 | 修法 |
|---|---|---|---|
| 1 | `qwen-fast` 引擎没加到入口白名单 | `-Engine qwen-fast` 直接报错，用不了 0.6B 快速引擎 | PS `-ValidateSet` + py `--engine choices` 补上 |
| 2 | `auto` 默认用 Kokoro | 本地模型配音实际走的是 Kokoro（中文 ASR 字错率 78%） | auto 改为优先 `qwen-fast`，失败自动回退 Kokoro 并记日志 |
| 3 | `customvoice` 不认 `TextFile=` | 视频配音传长文本时 TTS 报“缺少 Text”，静默回退 Kokoro | 支持 `TextFile/InstructFile`，与 voicedesign 一致 |
| 4 | 中文路径字幕烧录失败 | 加 `-BurnSubtitles` 时字幕不出现（ffmpeg subtitles 滤镜路径转义） | SRT 复制到 ASCII 临时目录，ffmpeg 在该目录以相对文件名烧录 |
| 5 | 自动配音失败仍返回 0 | 上游流水线以为成功 | 无产物时 `sys.exit(2)` |
| 6 | TTS 指令被字幕/字体要求污染 | 指令里混入“字幕要求/字体/颜色/位置”，TTS 语速怪异 | `_sanitize_instruct()` 只保留音色/语气/语速/情绪（最多 120 字） |
| 7 | 旁白长度按固定 5 字/秒 | 慢速 TTS 生成 9.6 秒音频配 4 秒视频 | 按引擎实测语速（qwen-fast 1.6 字/秒等）先算目标字数再让 LLM 写完整短句 |
| 8 | 超长音频 2× 加速后硬截断 | 尾句被切断、突兀 | 上限降为 1.8×，截断时加 150ms 淡出，并提示“尾部截断” |
| 9 | 旁白可能以逗号结尾 | SRT/听感都是残句 | 末尾标点规范化为 。！？ |

## 实测（4 秒测试片）

| 用例 | 结果 |
|---|---|
| `auto`（→ qwen-fast）+ 烧字幕 | 退出码 0，4.04 秒成片，video+audio 双流，中文“一叶扁舟静泊湖心…”字幕已烧录 |
| `-Engine kokoro` + 烧字幕 | 31.4 秒，音频 3.78 秒匹配 4.04 秒视频，无截断 |
| 直连后台 qwen-fast | 音频 3.92 秒 vs 视频 4.04 秒，无需压缩 |
| 直连后台 kokoro | 音频 5.05 秒 → 1.25× 加速，无截断 |

产物样例：`video-0062`（qwen-fast）、`video-0066`（Kokoro），均在 `桌面\视频\`。

## 流程现在的行为

1. 视觉理解（qwen3-vl 抽 3 帧）→ 本地 qwen3.5 生成配音提示词
2. 后端再让本地 LLM 写“目标字数内、完整一句话”的旁白
3. TTS 引擎：auto→qwen-fast（0.6B CustomVoice），可显式选 `qwen`/`kokoro`/`cosyvoice`/`chatterbox`/`seedvc`
4. 音效处理（音调/共振峰/音色）→ 时长适配（≤1.8×，必要时淡出截断）
5. 字幕对齐（对适配后的音频）→ 需要时烧录 → 封装（视频流 + 新音轨，去掉原音轨）
6. 产物：`video-NNNN-promptdub-时间戳.mp4` + 配音 wav + SRT

## 仍存在的限制

- 4 秒级短片的旁白内容受 LLM 随机性影响（有时偏短留白，偶尔语速慢）
- 若音频超过 1.8× 上限仍会被截断（已有淡出 + 日志提示）
- 本地 LLM 生成的旁白质量取决于 qwen3.5:9b，长片建议人工润色
- 引擎冷启动：qwen-fast 约 30~90 秒/次，qwen 1.7B 约 40 秒/次
